# Decisions

- 2026-10-25: Workspace was empty, so initialize a new app rather than adapt existing code.
- Use SQLite for local-first setup and Prisma's provider/config split for PostgreSQL compatibility.
- Treat the demo Director password as a one-time local seed credential and require a change on first sign-in.
- Use explicit role grants for multi-role users; authorization must be centralized and data scope checked server-side.
- Defer any module that cannot be implemented and verified to docs/ROADMAP.md rather than exposing nonfunctional controls.

- 2026-10-25: Demo users share one temporary local-only password and are forced to change it at first login; setup generates a random 32-byte signing secret for `.env`.
- 2026-10-25: This checkpoint exposes learner directory data only to Director, Head Teacher and Deputy because other role-to-record assignments are not yet modeled.
- 2026-10-25: Prisma SQLite setup runs with `RUST_LOG=info` because the bundled Prisma schema engine otherwise returned an empty Schema engine error in this Windows environment.
- 2026-10-25: Keep the local prototype honest about incomplete CBE, finance, operations and family portals; do not enable generic actions that would imply those workflows work.
- 2026-10-25: Use 80/60/40 as the initial EE/ME/AE boundaries (below 40 is BE); thresholds remain configurable work for the grading module and should be confirmed with school leadership before real grading.
- 2026-10-25: Use `MR-01`, `MR-02`, … as the sequential admission-number format for new learner records; generate the value server-side within the admission transaction. Existing seed records keep their original identifiers.
- 2026-10-25: The school motto is “Hard work pays”; keep “Nurturing Excellence Through CBE” as the portal’s CBE descriptor.
- 2026-10-25: Teachers alone create and edit learner assessments; the Head Teacher reviews, and the Director can release approved results but cannot enter marks. This follows the school’s separation of teaching and executive oversight.
- 2026-10-25: Director dashboards show schoolwide fee collection, outstanding balances, enrollment, attendance and payroll aggregates. Payroll is prepared by the Head Teacher and authorized by the Director; entries have version history, with synthetic sample values for local demonstration only.
- 2026-10-25: Frontend product research reviewed the public feature descriptions for [SAMIS](https://www.samis.co.ke/), [Masomo 360](https://www.masomo360.com/), [OLP Monitor](https://olpmonitor.tech/) and [Kenya’s NEMIS](https://www.education.go.ke/nemis). Applied patterns: role-specific dashboards, connected fee and learner records, CBC strand/competency presentation, mobile access, and explicit approval/audit trails. These are UX references only; no external product or service is connected.
- 2026-10-25: The supplied Mary Royal Junior School logo is used in the application and a square app icon is generated from it. The fixed navigation uses deep royal blue in light mode and a darker navy blue in dark mode; selected and inactive links retain readable contrast.
- 2026-10-25: Add a self-service profile area for photo and password updates. Profile photos are limited to PNG/JPEG/WebP, 2 MB, checked against file signatures and stored under random names. Password changes require the current password after initial setup. Use a signed, HTTP-only 10-minute idle token refreshed by active server requests, alongside a client inactivity timer.
- 2026-10-25: The Director’s header eye icon is a discreet shortcut to the existing privileged audit trail, not covert monitoring. It exposes recorded sign-in outcomes and sensitive system actions only; passwords, credential slips, and private message content are not logged.
- 2026-10-25: Apply the saved light/dark theme with a tiny `beforeInteractive` script on the document root so the chosen palette is in place before the first paint. Seed two terms of sample fee invoices and partial payments so executive finance dashboards are useful on first setup; keep amounts clearly synthetic.
- 2026-10-25: Retire the Accountant role. Head Teacher prepares invoices/payroll and confirms Secretary-entered payments; Director retains payroll authorization and schoolwide oversight. Secretary records admissions and family payments. Admissions are created as pending and approved by the Head Teacher; the Director sees the approval/audit record. This applies the user's more specific Secretary workflow after earlier wording that described Director approval of every admission.
- 2026-10-25: Migrate any old Accountant login to a suspended Head Teacher legacy account rather than deleting user/history. New setups do not create an Accountant login. A Director can review/reactivate/migrate any affected account.
- 2026-10-25: Class attendance is a separate explicit Class Teacher assignment. Subject assignment alone never grants permission to mark attendance.
- 2026-10-25: Daily teaching logs are authored by assigned teachers; Head Teacher or Director confirms. Assignments are grade/subject scoped, learner submissions are linked to the learner account, and auto-marking compares a short exact-answer key. The optional AI draft uses local Ollama only and clearly reports when no local model is available.
- 2026-10-25: Parent complaints are private threads routed to an assigned class teacher or school leader. Secretary can log an in-person complaint on behalf of a parent, learner or Head Teacher. Learner accounts do not receive complaint navigation or API access; Head Teacher and Director can review schoolwide threads while other staff see only threads assigned to them.
- 2026-10-25: Create an individual learner login automatically with each new admission using the lower-case admission number as a unique school email. Show a random temporary password once in a printable credential slip, hash it immediately, require a password change at first sign-in, and keep the account suspended until a pending admission is approved by the Head Teacher.
- 2026-10-25: Provide a learner-only learning space with grade-scoped teacher resources, assignment marks, released assessment progress and saved educational game attempts. Teacher resources accept HTTPS links only; video embeds use privacy-enhanced YouTube, Vimeo or direct MP4/WebM links. No external AI or personal learner data is sent from the game or media views.
- 2026-10-25: Place the theme initializer in the root document `<head>` with Next.js `beforeInteractive` ordering. Internal workspace navigation uses Next `Link` to reuse client routing/prefetch, reducing avoidable full document reloads.
- 2026-10-25 (Round 2): Reintroduce ACCOUNTANT as a distinct role. Secretary may admit/edit learner records and explicitly create learner access, but can only read invoice totals/paid/balance and cannot record, approve, void, or access receipt details.
- 2026-10-25 (Round 2): Learner and parent logins are opt-in, separately created after admission or from an authorized learner profile. Existing parent accounts should be matched and linked by normalized phone/ID rather than duplicated when those fields are available.
- 2026-10-25 (Round 2): Complaints are private Parent-originated threads directed to the Head Teacher, Director, or both. No staff role other than those two leaders can view or mutate the complaint inbox.
- 2026-10-25 (Round 2): Default setup/reset is an empty production-shaped school with a forced-password-change Director and CBC defaults. Synthetic fixtures are available only through `seed:demo`, including when preparing E2E runs.
- 2026-10-25 (Round 2): Learner data visible to the Secretary is limited to admission and records-desk needs; medical details require explicit role checks and access audit. The legacy simple admission form is not equivalent to the requested full multi-step admission pack and must not be presented as such until that workflow is implemented.
- 2026-10-25 (Round 2): Parent navigation returns to `/portal`, Learner navigation to `/learning`, and staff navigation to `/dashboard`. Keep route history scoped by authenticated user in `sessionStorage`; use the route's parent/home fallback when no same-tab in-app history exists, and preserve scroll position without storing learner data or form contents.
- 2026-10-25 (Round 2 U4): Store admission biography, residence, restricted health, guardians and contacts in normalized profile tables; store uploads outside `public/` under random names and expose them only through permission-checked, audited routes. Health-section reads create a separate access event without recording health values.
- 2026-10-25 (Round 2 U4): Admission submit creates a pending learner record and never creates an account implicitly. Learner and parent accounts are explicit post-submit actions; new accounts remain suspended until Head Teacher enrollment approval. Match parent accounts using normalized Kenyan phone and government ID fields; if the identifiers point to different accounts, require Director review instead of guessing.
- 2026-10-25 (Round 2 U4): The Secretary records fee responsibility and optional service requests at admission, but does not price invoices or record payments. Use the Head Teacher/Director approved fee structure for actual billing when U9 is complete; do not invent admission-time amounts.
- 2026-10-25 (Round 2 U4): Keep `/admissions/new` as a transient creation entry route; replace it in per-user navigation history with the generated draft ID so Back returns to the learner register rather than starting another draft.
# Round 2 profile access
- Learner profile access reuses the central learner and finance permission scopes. Accountant gets a separate `learner-identity` scope and only name, admission number, grade and permitted fee balances; it does not receive family, academic, medical or discipline details.
- Health details are fetched only for Director, Head Teacher, Deputy, Secretary and the learner's class teacher. Each view writes an audit event. Parents and learners do not see medical data in this iteration.
- Staff views use the new `staff` permission resource. Director and Head Teacher can browse staff profiles; staff roles can open only their own profile. Existing payroll rows are Director-only. Employment fields absent from the schema (TSC, qualifications, punctuality and staff attendance) are explicitly identified instead of synthesized.
- The learner video library treats the Edu TV Kenya handle (`@edutvkenya`) as the allowed source because KICD's official services page links its Edu Channel section to that YouTube handle. The server verifies YouTube oEmbed's author URL host and path before saving the canonical title and video ID. It requires internet access to curate; already verified lessons play from the local catalogue.
- 2026-10-25: Treat generic teacher-shared video resources as ordinary class resources, not as verified curriculum recommendations. Learner revision recommendations come only from the curated `LearningVideo` catalogue after KICD Edu TV channel verification, matched to released assessment weaknesses; an empty match produces an explicit empty state.
- 2026-10-25: Isolate Playwright from the developer's active local server using the dedicated `3187` port and a separate `.next-e2e` build directory. Do not let E2E silently test an older running app when the requested test server starts on another port.
- 2026-10-25 (Round 2 U9): Head Teacher and Director own fee structures. Keep each class/term version and its effective date; invoice lines snapshot the structure version so future changes never rewrite issued amounts. Secretary and Accountant may view the structure, while only Head Teacher/Director may create a version.

- 2026-10-25 (U5): Learner passport photos are served only from private admission storage through a scoped, no-store route; document previews and downloads are private, permission-checked, and audited. Secretary, like Director/Head Teacher/Deputy, may access the full learner admission record. Accountant receives fee balance and guardian contact information but no academics, discipline, residence, or health. Teachers receive only assigned learners, with health data limited to class teachers.
- 2026-10-25 (U5): Store TSC/staff number, qualifications, position, and staff attendance as explicit profile fields/records. Director/Head Teacher/Deputy may view and record schoolwide staff registers; other staff see their own attendance.
- 2026-10-25 (U11): The user requested completion through U11 although the supplied Round 2 brief ends at U10. Define U11 as final acceptance and hardening: execute full route/IDOR and browser suites, build and local smoke test, reconcile docs/roadmap, and confirm all incomplete requested functions. U11 is not a deployment phase; any U4/U6/U7/U9/U10 remainder remains explicitly open until implemented.
